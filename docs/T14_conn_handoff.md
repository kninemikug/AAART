# T14-CONN 검색 연결 인계

갱신일: 2026-10-15. 입력에 없는 제품명 추가와 보존값의 접사 문제를 보완했다. 고유 입력 104개의 새 실제 생성·전체 A/B·G1~G3 및 경로 재현성 보완 후 전체 테스트 796개를 통과하여 T14-CONN 완료로 판정한다. [최종 보고서](../data/eval/t14-conn/conn_20261015_pr/report.md)를 인수한다. 이전 수치 통과만으로 제품 범위 보존 완료를 선언한 판단은 정정하며 과거 기록을 보존한다. T17 답변 연결과 T16 폴백은 각 카드에서 구현·검증하며 현재 미완료다.

## 1. 검색 연결 입력

- 검색 진입점은 `create_search_nodes(store, session, generate=..., snapshot_ref=..., rewrite_enabled=..., hyde_enabled=False)`다. 기존 `create_router_graph(node_overrides=...)`의 두 검색 노드를 교체한다.
- 생성 콜백은 `prompt → str` 계약이다. T11 생성 헬퍼의 응답을 검사해 검색 문장만 반환하고, 실제 생성 모델·설정·원응답·호출·시간을 기록한다. 평가 캐시를 일반 요청의 생성기로 사용하지 않는다.
- `literal_preservation_v3`는 제품명·파일명·빌드명·숫자 원형을 보호하고 입력에 없는 ART/RawTherapee의 추가를 거부한다. 보존값을 독립된 토큰으로 복사하며 접사·하이픈 결합과 숫자의 서수 접미사를 금지한다. 원질문과 확정된 OS·버전·목표·제약에서 보존값과 허용 제품을 추출하며 정답 문서 ID나 기대 답변은 입력하지 않는다. 제품 검사는 대소문자·조사·실행 파일 표기와 ART의 정식 명칭을 다루며, 임의의 모든 제품명을 판별하는 검사는 아니다.
- 생성 또는 보존 검사 실패는 `REWRITE_FAILED`와 검색 호출 없음으로 끝낸다. 허용 범위 밖 제품명은 세부 분류 `PRODUCT_SCOPE_VIOLATION`으로 기록한다. 저장소·근거 매핑 오류는 `SEARCH_UNAVAILABLE`이다. 정상 빈 결과와 두 오류를 구분한다.
- `request`, `decision.plan`, `cursor`, `research_count`는 검색 노드에서 변경하지 않는다. HyDE는 off이며 가상 문서를 근거에 넣지 않는다.
- 기본 팩터리는 재작성 off다. 채택된 인수 호출에는 `rewrite_enabled=True`, `hyde_enabled=False`를 명시한다. 동일 입력의 off 경로도 비교·대체 설정으로 유지한다. 품질 판정과 실제 서비스 연결 완료를 별도로 기록한다.

## 2. T17 — 실제 답변·인용 연결

소유 카드: [Task 17](../tasks/todo.md). 담당 김구. 검색 연결과 병행하여 off 경로로 준비할 수 있으며, on 채택이 확인되면 동일 답변 경로의 설정만 바꿔 비교한다.

1. 현재 `RetrievalBundle`을 입력으로 T11의 문맥 구성·생성·인용 헬퍼를 사용한다. 전체 `run_pipeline`을 호출하여 검색을 중복 실행하지 않는다.
2. `Evidence.text`는 해당 원문 세그먼트의 텍스트다. `doc_id`, `source_group_id`, `source_path`, `target_url`, `product_scope`를 보존한다. RawPedia 근거의 RawTherapee 범위를 ART 지원 확정으로 바꾸지 않는다.
3. `source_location`은 `section_title`과 전체 `source_segment`를 가진 정규 JSON 문자열이다. 여기서 원문 파일·JSON pointer·문자/바이트 범위·파일/본문 해시·참조 ID를 읽는다. 표시 제목에는 section title을 쓰고 인용 위치에는 실제 위치 정보를 유지한다.
4. 근거 답변은 인용을 하나 이상 반환한다. 미지원과 근거 부족을 구분하여 `SUPPORTED`, `UNSUPPORTED`, `INSUFFICIENT_EVIDENCE`를 반환한다. 검색 Hit나 골드 도달 여부로 답변 상태를 결정하지 않는다.
5. Slice 1의 같은 15개에서 실제 답변의 주요 사실·제품 범위·인용 연결을 기존 T11 기록과 대조한다. Q001·Q086·Q096 수동 검토와 CP2 양성 표본의 근거 답변을 확인한다.

현재 B의 Q024·Q030·Q070은 상위 5개 검색 미도달 사례다. Q030은 A의 1위에서 미도달로 바뀌었고, 전체 10개 양성 질문의 개별 순위가 A보다 낮아졌다. 집계 비저하가 모든 질문의 순위 비저하를 뜻하지 않는다. 이 사례들은 T15 검색 튜닝 입력으로 넘긴다.

Q010·Q077의 ART 추가는 T14에서 수정·재검증을 끝냈다. 현재 B 검색 순위는 각각 1·3위이며 실제 근거의 `product_scope=RawTherapee`를 보존했다. T17은 이 결과와 별도로 실제 근거의 제품 적용 범위를 검증한다. 검색 점수만으로 이 질문들을 근거 답변 완료로 처리하지 않는다.

현재 검색 실행의 `ANSWER`와 준비 상태는 대역이다. 최종 답변·인용 품질, 프로필·렌더 성공, CP3의 답변 동등성을 증명하지 않는다.

## 3. T16 — 근거 부족 1회 폴백

소유 카드: [Task 16](../tasks/todo.md). 담당 고태우. T17의 상태 계약이 준비되면 대역으로 예산·종료 테스트를 먼저 작성하고 실제 답변 노드와 연결한다.

- T17이 명시적으로 `INSUFFICIENT_EVIDENCE`를 반환할 때만 추가 재작성→검색→답변을 요청 전체에서 한 번 허용한다.
- `UNSUPPORTED`와 기술 오류에서는 추가 검색을 하지 않는다. 다시 근거 부족이면 종료하며 점수 기반 신뢰도 판정이나 추가 재시도를 넣지 않는다.
- 추가 입력을 준비한 뒤 최초 검색 어댑터가 다시 재작성하는 중복 호출을 막는다. 항목·시도별 준비 여부의 state 읽기/쓰기·재개 계약을 T16에서 먼저 정한다.
- `research_count`는 요청 전체의 추가 검색 예산이다. 혼합 요청의 서로 다른 항목에 필요한 최초 검색까지 생략하는 신호로 쓰지 않는다.
- 1회/종료, 미지원/오류의 추가 검색 없음, 혼합 항목, 재개 후 count 보존과 완료 항목 중복 없음의 실행 기록을 남긴다.

T17과 T16의 실제 연결·회귀를 확보한 뒤 CP3를 판정한다. 검색 연결 카드 완료만으로 CP3를 닫지 않는다.

## 4. 확대 평가 인계

현재 100개는 T8-2부터 사용한 탐색·회귀 질문이며 독립 홀드아웃이 아니다. 전체 100개 안의 GitHub 양성 15개와 검색 연결 대조용 Slice 1 15개를 별도의 독립 표본으로 합산하지 않는다.

확대 평가는 `tasks/todo.md`의 독립 평가셋 준비 카드와 기존 최종 답변 스택 선정 게이트가 소유한다. 새 질문과 원문 범위, 독립 문서/스레드 수, 유형 구성·표본수·추출 방식·공수를 후보 답변을 보기 전에 고정한다. 기존 100개의 반복 실행을 확대 평가로 표시하지 않는다.

새 코퍼스가 필요하면 T10 정제와 T9 색인 인수를 거쳐 별도 스냅샷을 고정한다. 최종 스택 선정 게이트의 실제 T15·T17 경로에서 검색·답변·인용·지연/비용을 함께 평가한다. T23은 기존 계약의 100개 RAGAS와 표본 한계를 별도로 보고한다.
