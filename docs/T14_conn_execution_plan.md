# T14-CONN 실행 플랜 — A-14 최초 검색 연결

작성일: 2026-10-14. 갱신일: 2026-10-15. 상태: 구현 기준 플랜. 후속 구현과 보완 검증의 현재 상태는 §12 및 최종 연결 보고서에서 확인한다.

## 1. 목적과 WBS 위치

[연결 후속 검토](T14_conn_followup_review.md)의 결론을 실행 순서와 완료 증거로 구체화한다. [실행 WBS](ART_agentic_wbs.md) §5 A-14에 이미 포함된 **재작성 모듈의 T13-2 그래프 연결**을 소유 카드 `T14-CONN`으로 추적한다. 단독 T14 구현·실측 평가는 완료됐으며 이 플랜은 남은 연결분을 다룬다.

이번 S 카드의 구현은 T14 최초 재작성·T9 실제 검색 어댑터까지다. T17 답변과 T16 폴백은 같은 CP3 단계의 필수 작업으로 병행 준비하되 각 기존 카드가 구현·연결·검증을 소유한다. HyDE는 off로 유지한다. T14-CONN 완료, WBS A-14 완료, CP3 완료를 각각 보고한다.

기준은 원격 `main`의 `9c541df32204ae9a331c2666f8fc52e591ba9113`에서 검토한 WBS·설계·인터페이스다. 후속 구현 착수 때 최신 기준의 관련 파일 변경을 다시 확인하고 입력·코드 지문을 새 실행 기록에 남긴다. 기존 브랜치나 다른 작업의 변경을 덮어쓰지 않는다.

| 범위 | 결정 |
|---|---|
| 이번에 연결 | `SEARCH_RAWPEDIA`·`SEARCH_GITHUB` 안의 최초 재작성, T9 출처/지정 글 필터, 실제 `Evidence` 변환·스냅샷 연결 |
| 별도 정점 | 새 `REWRITE` 정점 없이 기존 `create_router_graph(node_overrides=...)` 사용 |
| 변환 설정 | 팩터리 기본 off를 유지하고, 검증된 인수 호출에서 `rewrite_enabled=True`, `hyde_enabled=False`를 명시. 비교는 off/on |
| 이번 카드 밖 | T17 답변 상태·인용 구현, T16 재검색 루프, T15 리랭킹·k 튜닝, P3 서비스 구현, 추가 HyDE 실험 |
| 공수 | A-14 전체의 기존 계획 3h 안에서 연결분을 분해. 실제 사용·잔여 예상 시간은 착수 시 기록하며 부모/하위 카드를 중복 집계하지 않음 |

## 3. 구현 계약

### 3.1 T9 필터와 결과 계약

현재 `RetrievalStore.search(query, session, *, source_key=None)`는 고정 top5를 반환한다. 기존 `SourceKey`는 출처와 단일 그룹을 동시에 요구하므로 출처만 지정하는 P1/P2 검색을 표현할 최소 보완이 필요하다.

| 항목 | 후속 구현 결정 |
|---|---|
| 선택적 범위 인자 | `source_type`과 `source_group_ids`를 검색 API에 선택적으로 추가하는 안. 기존 인자·기본 동작·단일 `SourceKey` 호출은 유지 |
| 출처 | 그래프 `RAWPEDIA/GITHUB`를 T9 `rawpedia/github`로 변환. 검색 전에 제한 |
| 지정 글 | 원요청의 Issue/Discussion 종류·번호·URL에서 정제 후보의 실제 그룹 ID를 결정. 복수 명시 대상을 모두 포함하고 번호만으로 두 종류를 혼동하지 않음 |
| 범위 없음/빈 범위 | 그룹 범위 없음은 해당 출처 전체. 명시적인 빈 그룹 집합은 정상 빈 결과이며 전체 검색으로 확대하지 않음 |
| 기존 키와 신규 범위 | 같은 출처·그룹이면 교집합 의미로 적용. 서로 모순되면 계약 오류로 거부 |
| 불변 조건 | `excluded=False`, 동일 encoder·모델·리비전·벡터 정책·정렬·k=5. 적재·갱신·삭제·재색인 없음 |
| 반환 | 순위·본문·해시·모든 `source_segments`·원본 메타데이터를 가진 기존 `SearchHit` 유지 |

전체 top5를 검색한 후 다른 출처를 제거하는 후처리는 사용하지 않는다. 평가 질문의 `source_type`·정답 문서 ID·골드 위치로 검색 범위를 만들지 않는다. 실제 라우팅 결정과 원요청의 제약만 사용한다.

### 3.2 두 검색 노드의 처리 계약

후속 `src/artagent/graph/search.py`는 저장소·encoder session·생성 콜백·스냅샷 참조·재작성 설정을 받은 두 노드 구성을 제공한다. 최종 공개 함수명은 구현 시 기존 스타일에 맞추되 아래 읽기/쓰기 경계는 고정한다.

| 계약 | 고정 내용 |
|---|---|
| 입력 | 현재 `decision.plan[cursor].query`, 원요청·확정 context/제약, 선택된 P1/P2 출처와 지정 원문 대상 |
| 순서 | 원질문으로 라우팅 확정 → T14 입력 준비 → 필터를 적용한 T9 검색 → 실제 원문 세그먼트 매핑 |
| on/off | on 최초 검색 항목에서 생성 콜백 1회, off에서 0회. 실제 생성 또는 캐시 재생 여부와 신규 서비스 호출 수는 별도 기록. HyDE 호출 0회 |
| 생성 어댑터 | T11 헬퍼의 JSON/tuple을 검증해 검색 변환 문자열만 반환. 모델·설정·원응답·실측 시간은 별도 기록하며 JSON 전체를 질의로 사용하지 않음 |
| 정상 출력 | `retrieval=RetrievalBundle(query=실제 검색 문자열, source_filter=선택 출처, hits=실제 Evidence, snapshot_ref=검증 참조)`, `error=None`, 기존 노드명을 기록한 trace |
| 원문 매핑 | 세그먼트별 실제 doc/ref ID·URL·파일·JSON pointer/byte/char 범위·제품 범위와 해당 텍스트를 보존. 전체 부모 `SearchHit`는 기록에 유지 |
| 제품 범위 | RawPedia의 RawTherapee 참고 범위와 ART 원문 스냅샷 범위를 명시. `Evidence.product_scope`의 기본값 `ART`에 일괄 의존하지 않음 |
| 변환 실패 | `ErrorInfo(code=REWRITE_FAILED, node=현재 검색 노드, recoverable=False)`; 검색·답변 호출 0회. 세부 T14 오류는 진단 기록에 보존 |
| 검색 서비스 실패 | `SEARCH_UNAVAILABLE`로 항목 실패. 빈 정상 결과나 근거 부족으로 치환하지 않음 |
| 빈 정상 결과 | `hits=[]`인 정상 bundle. 근거 충분/미지원/근거 부족 상태는 T17이 결정 |
| state 불변 | 최초 검색에서 request·계획·cursor·research_count를 갱신하지 않음. 재작성으로 경로·실행 목표·의존을 바꾸지 않음 |

`search_with_rewrite`에 T9 메서드를 그대로 전달하지 않는다. 래퍼는 `k`·`source_filter` 인자를 전달하지만 T9는 encoder session을 요구한다. 이 계획은 `prepare_search_input`과 session을 가진 실제 T9 호출을 연결하는 방식을 사용한다.

현재 `IntentSignals.constraints`는 추출에서 빈 목록이므로 여기에 정보가 이미 있다고 가정하지 않는다. 원요청·현재 항목·확정된 OS/버전/제품 조건을 제약으로 전달하고 Q010·Q077의 제품 범위 위험을 검증한다. 새 제약으로 프롬프트가 바뀌면 새 실제 생성 기록을 사용한다.

## 5. 연결 후 검증과 기록 형식

### 5.1 세 검증 집합

## 12. PR 인수 전 기록 경로 재현성 (2026-10-15)

PR 준비 검토에서 인계 기준 파일이 실행 폴더의 절대 경로로 기록되어 다른 체크아웃에서 검증이 실패할 수 있음을 확인했다. 새 기록은 저장소 상대 경로를 사용한다. 과거 절대 경로는 현재 저장소 `docs/`의 같은 이름 파일로 해석하고 기존 SHA-256·모델·스냅샷 검사를 그대로 적용한다. 상대 경로의 저장소 이탈은 거부하며 실행기의 새 기준 파일도 저장소 내부로 제한한다.

다른 체크아웃 경로, 다른 작업 디렉터리, 기준 파일 해시 불일치와 저장소 이탈 회귀에서 보완 전 3개 실패·1개 통과를 확인한 뒤 4개 모두 통과했다. 생성·원형 보존 헬퍼와 프롬프트는 바꾸지 않았다. 고유 실제 생성 104개의 출처를 재사용하여 [PR 인수 기록](../data/eval/t14-conn/conn_20261015_pr/report.md)에 경로 40/40·Slice 1 대조 30/30·전체 A/B 200행과 G1~G3 통과를 새 코드 지문으로 남겼다. 추가 생성은 0회이며 검색 지표와 남은 한계는 §11과 동일하다.

전체 회귀는 796개 통과(260.20초), 외부 패키지의 폐기 예정 경고 1건이다. 다른 작업 디렉터리에서 PR 인수 기록을 `--validate`로 검증해 G1~G3와 종료 코드 0을 확인했다. 이 결과로 국문 커밋·푸시·PR을 진행한다. 재작성 거부 시에는 `REWRITE_FAILED`와 검색 0회로 종료한다. 재작성 재시도나 원질문 검색 복귀는 추가하지 않았으며 T16의 근거 부족 재검색과 구분한다.
