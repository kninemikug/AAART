# RAG 답변 스택 선정 실험 계획

## 고정 문맥에서의 첫 비교

기준선 `gpt-5.6-sol`과 같은 계열의 경량 후보 `gpt-5.6-terra`, `gpt-5.6-luna`를 기존 `codex-cli` 답변 경로에서 비교한다. 같은 CLI와 T17 프롬프트를 사용해 제공처와 문맥의 차이를 통제한다. 세 모델은 작업 환경의 모델 목록에서 확인했다. 추론 강도와 temperature는 기존 CLI 기본 설정을 유지하며 서버가 값을 제공하지 않으면 미확인으로 기록한다. [GPT-5.6 모델 계열](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6)

첫 비교는 T15 채택 B 경로의 보존 문맥이 있는 기존 회귀 질문 `Q001`, `Q033`, `Q070`, `Q086`, `Q092`, `Q096`을 사용한다. 원문 출처가 각각 세 개이며 단일 사실, 복합 질문, 근거 부족, 미지원 처리를 포함한다. `data/eval/ragas_v1/inputs.jsonl.gz` 안의 동일 질문·세그먼트·순서를 각 모델에 넘긴다. 원문 검증과 인용 조립은 실제 `answer_standalone`을 사용하고, 생성 프롬프트 지문이 보존된 T17 답변의 지문과 일치하는지 검사한다. 보존된 Sol 답변은 계보 확인용으로 연결하고 지연 비교용 Sol은 동일 환경에서 실제 호출한다.

- 모델별 문항당 한 번, 최대 18개 생성 요청을 등록한다. 기존에 완료된 모델·질문 쌍을 재호출하지 않는다. 기술 오류는 시도 건수에 포함하고 자동 재시도하지 않는다.
- `Q001`, `Q033`, `Q086`, `Q092`의 목표 상태는 `SUPPORTED`, `Q070`은 `INSUFFICIENT_EVIDENCE`, `Q096`은 `UNSUPPORTED`이다. 상태·주장·인용·제품 범위를 독립적으로 확인한다. 원문과 검색 문맥을 주장의 기준으로 삼는다.
- 우선 검증할 경량 후보는 기술 성공 6/6, 상태 정확 6/6, 중요한 무근거 주장·제품 범위 위반·잘못된 인용 각 0건을 만족해야 한다. 만족하는 후보 중 생성 지연 중앙값이 동시대 Sol 이하인 후보를 우선하고, 공개 API 요금으로 추정한 사용량 비용이 Sol보다 낮은지도 본다. 실제 CLI 과금과 API 환산액은 별도 기록하며 미제공 값은 `null`로 남긴다. 이 비교의 승자는 독립 평가에 넘길 우선 후보에 해당한다.

## 독립 최종 평가의 선행 작업

T8-1의 골드 원문 집합, 조정용 질문의 골드 원문 집합과 다른 문서·스레드로 최종 질문을 작성한다. RawPedia에는 기존 스냅샷에 여유가 있고 GitHub는 기존 스냅샷의 검색 가능 스레드 12개 전부가 기존 질문셋에 쓰였다. GitHub 독립 표본은 보존 원문에서 새 스레드를 검토해 T10 정제 규칙과 T9 재색인 경로를 거친 실험 스냅샷을 사용한다. 지정 글 없는 질문, 복합 조건, 미지원, 근거 부족을 포함하고 질문·원문 위치·기대 행동·분리 지문을 고정한다.

개발 단계의 조정은 개발 집합에서만 한다. 최종 후보·프롬프트·검색 설정을 고정한 뒤 독립 집합에서 Sol과 후보를 비교하며, 품질·인용·상태·제품 범위 기준을 만족하고 기술 성공률과 지연이 악화되지 않았는지 확인한다. 최종 선정 또는 보류 근거와 증거를 T23에 인계한다. 기존 T8-1 100문항은 회귀 평가에 사용한다.

독립 입력은 [RawPedia 4문서와 GitHub 4스레드의 8문항](../data/eval/stack-selection/final_questions_v1.json)이다. 입력 SHA-256은 `222813bc4ca316ab459c6ac252c8c220ae069a0c6be4e400e16a0f84498ccfae`다. 기존 T15 스냅샷을 먼저 복원하고 T10 정제와 T9의 고정 GitHub 청킹 규칙으로 Issue #317·#445·#518·#522를 실험 저장소에만 추가한다. 검색 출처는 질문에 함께 등록한 값을 사용한다. Issue 번호가 없는 F06은 해당 출처 내에서 대상 글 필터 없이 검색한다. 재작성은 고정 Sol과 T14 경로로 문항당 최대 1회 호출하며 HyDE는 사용하지 않는다. BM25는 확대된 실험 코퍼스에 적합하고 T15 후보 20·top 5·최소 점수 0.5·가중치 0.25를 유지한다.

독립 최종 비교는 Sol과 Terra, 변경 전 `t17-answer-v1` 프롬프트로 고정한다. Terra는 초기 비교에서 중요한 무근거 주장이 확인되지 않았고 Sol과 지연 차가 작은 후보였다. Luna는 근거 부족 답변에서 다른 예시의 스팟 수와 도구에 잘못된 세그먼트를 인용해 이 단계 대상에서 제외했다. 8문항의 실제 검색 bundle을 양쪽에 똑같이 전달하고 각 모델에 8회까지 요청한다. 기술 성공과 예상 상태는 8/8, 중요한 무근거 주장 및 잘못된 인용은 0건, 답변 지연 중앙값은 Sol 이하, 공개 API 토큰 단가 환산은 Sol보다 작아야 한다. 비교 결과가 부족하거나 기준에 미달하면 선정 보류로 기록한다.

## 저비용 API 후속 비교

NVIDIA 개발용 무료 엔드포인트가 있는 `z-ai/glm-5.3-flash`와 `minimaxai/minimax-m3.1-flash`를 같은 회귀 질문 6개와 동결한 T17 문맥에서 비교한다. 6개에서 상태·중요 주장·인용·제품 범위·기술 성공 기준을 통과한 모델은 기존 독립 8문항에서도 확인한다. 독립 표본을 조정에 사용하지 않는다. 원문 기준을 충족한 모델의 원 제공사 환산 비용을 비교하고 지연과 실패를 함께 남긴다. 기존 Terra 결과는 품질 기준선이다. [GLM NVIDIA 엔드포인트](https://build.nvidia.com/z-ai/glm-5-3-flash) · [MiniMax NVIDIA 엔드포인트](https://build.nvidia.com/minimaxai/minimax-m3.1-flash)

NVIDIA 응답의 `prompt_tokens`와 `completion_tokens`를 원 제공사의 정규 입력·출력 단가에 각각 곱한다. 다른 제공사의 캐시 적중률은 환산에 적용하지 않는다. 응답 검증에 실패했더라도 사용량이 제공되면 추정 비용에 포함한다. 사용량 누락은 건수를 기록하고 실제 과금은 `null`로 보존한다. 초기 12회, 독립 표본은 통과 모델당 최대 8회 호출한다. 모델과 문항당 한 번 실행하고 재현 집계는 보존 응답을 사용한다. [Z.ai 단가](https://docs.z.ai/guides/overview/pricing) · [MiniMax 단가](https://www.minimax.io/blog/minimax-m31f)
