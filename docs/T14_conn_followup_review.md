# T14 → T13-2 연결 후속 검토 초안

검토일: 2026-10-14. 상태: 전체 WBS 관점 보완 초안이며 연결 구현·연결 후 테스트 결과가 아니다. 최초 초안의 인접 태스크 검토에 더해 WBS §0~§10, Phase A 실행 계획과 상세 카드의 범위·공수·체크포인트·후속 의존 관계를 대조했다. Phase B/C 모든 구현의 실제 완료 여부를 감사한 문서는 아니다.

## 1. 결론과 검토 기준

**T14의 단독 구현·평가 완료와 그래프 연결 완료는 별도로 관리해야 한다.** [T14 플랜 §8](T14_execution_plan.md#8-t13-2-완성-후-그래프-연결-계획)의 최초 검색 연결을 소유할 `T14-CONN` 카드를 신설한다. 이번 카드의 범위는 **T14 최초 검색 재작성 + T9 검색의 T13-2 접합**이다. T17의 답변 노드와 T16의 근거 부족 폴백은 각각 기존 카드의 연결 책임으로 남긴다. HyDE는 비활성화한다.

**WBS A-14의 전체 범위에는 그래프 연결이 이미 포함돼 있다.** T14-CONN은 기존 A-14의 남은 연결 작업을 분해한 소유 카드이며 새 기능이나 별도 3시간을 추가하는 카드가 아니다. 단독 T14의 완료 기준 충족만으로 WBS A-14 전체 또는 CP3를 닫지 않는다. 전체 WBS 영향과 공수 처리 원칙은 §7에 정리했다.

T13-2 병합 완료는 연결의 선행조건을 충족하지만 실제 검색·답변·폴백 연결 완료를 뜻하지 않는다. 현재 `nodes.py`의 `SEARCH_RAWPEDIA`, `SEARCH_GITHUB`, `ANSWER`, `RESEARCH` 기본 함수는 모두 `CAPABILITY_UNAVAILABLE`를 반환한다. 이는 미연결을 성공으로 표시하지 않는 골격의 동작이다.

## 2. 이번에 연결할 범위와 소유자

| 대상 | 이번 카드의 결정 | 소유·인계 |
|---|---|---|
| T14 최초 검색 재작성 | 포함. P1/P2 검색 노드 내부의 서비스 호출 경계에서 `prepare_search_input`을 사용 | T14-CONN 담당 김대성 제안 |
| T9 검색·결과 변환 | 포함. 출처 필터, 지정 글, 동일 모델·컬렉션·k=5, 실제 원문 연결을 보존하는 얇은 어댑터 | T14-CONN 구현, T9 담당 김구 계약 검토 |
| 새로운 그래프 `REWRITE` 정점 | 추가하지 않음. 기존 두 검색 노드의 내부 처리로 연결 | T13-2의 경로·전이·state 작성 책임 보존 |
| T17 `ANSWER` | 이 S 카드의 구현 범위 밖이며 같은 CP3 접합 단계의 필수 작업. 세 가지 답변 상태와 인용 계약·실제 노드 연결은 기존 T17 카드가 소유 | 김구; T14-CONN과 병행 준비 후 `RetrievalBundle`을 인수 |

| T15·P3 | 리랭킹·k 튜닝·프로필·렌더 서비스 연결 제외 | 해당 태스크 유지; 경로 회귀만 검사 |

이번 연결의 기본 설정은 **호출 지점에서** `rewrite_enabled=True`, `hyde_enabled=False`를 명시한다. 현재 T14 모듈 자체의 기본값은 둘 다 `False`이므로 인자 없이 호출하면 재작성은 켜지지 않는다. 비교 실행은 동일 어댑터에서 재작성만 off/on으로 전환한다.

`create_router_graph(node_overrides=...)`의 기존 확장 지점에 실제 `SEARCH_RAWPEDIA`·`SEARCH_GITHUB`를 주입한다. `REWRITE`라는 이름을 overrides에 추가하면 현재 팩터리는 미등록 노드로 거부한다. 별도 정점·전역 재시도·새 라우팅 정책을 추가할 이유가 없다.

**완료 판정 경계:** T14-CONN은 검색 계층 연결 완료를 판정한다. T17 연결 전에는 그래프 기본 `ANSWER`가 미연결이므로 실제 답변 E2E나 CP3의 “Slice 1 데모가 그래프 경유로 동등 이상” 완료를 주장하지 않는다. 답변 대역으로 수행한 경로 검증과 실제 답변 실행 기록을 구분한다. T17 연결 이후에 답변 E2E 대조를 완료하고, T16 연결 이후에 근거 부족 재시도까지 검증한다.

### 3.1 검색 어댑터의 고정 처리 순서

1. `DISPATCH`가 선택한 현재 P1/P2 항목에서 원질문, 확정 제약, 출처 범위, 명시 원문 대상과 스냅샷을 읽는다. 경로는 재작성 전에 확정하며 생성된 문장으로 재라우팅하지 않는다.
2. 재작성 on은 해당 최초 검색 항목당 생성 1회, off는 0회다. HyDE 생성은 항상 0회다. T14 입력·프롬프트·출력·상태와 실제 런타임 정보를 남긴다.
3. 변환 성공 시 동일 T9 경로에서 검색 1회 수행한다. 출처·명시 대상 필터는 **검색 전**에 적용한다. 전체 top5를 받아 다른 출처를 지우는 후처리는 출처별 top5를 보장하지 않으므로 사용하지 않는다. 모델·청킹·임베딩·정렬·k는 유지한다.
4. 반환된 `SearchHit`의 전체 원문 연결을 보존해 `Evidence`로 변환하고 `RetrievalBundle`을 만든다. `snapshot_ref`는 컬렉션명만 적는 대신 인계 설정과 검증 기록의 지문으로 역추적되게 한다.
5. 최초 검색의 `request`, `decision.plan`, `cursor`, `research_count`는 변경하지 않는다. T14 생성 문자열을 `Evidence`에 추가하지 않는다. 완료 항목 재개에서 검색·생성을 중복 호출하지 않는다.

이번 최소 T9 보완은 출처 범위와 명시 그룹 집합을 표현하는 선택적 검색 필터까지다. 기존 `source_key`와 신규 범위를 함께 지정했을 때 모순을 거부하고 `excluded=False` 조건과 고정 정렬·top5를 보존해야 한다. 검색 전략 추가·모델 재선정·k 변경은 T15 범위로 남긴다.

`research_count`는 요청 전체의 **추가 재검색 예산**이지 최초 재작성 호출 수가 아니다. 혼합 요청의 서로 다른 P1/P2 항목은 각각 최초 재작성을 수행할 수 있다. 이후 T16이 현재 항목의 검색 입력을 준비하면 해당 재검색에서 최초 검색 어댑터가 다시 재작성하지 않아야 한다. 요청 전체 count만으로 모든 후속 항목의 변환을 생략하지 말고, T16 카드가 항목·시도별 준비 여부와 원질문 보존 계약을 먼저 확정한다.

## 4. 연결 후 검증안

### 4.3 Slice 1의 15개 기록 대조

Slice 1 고정 ID는 **Q001, Q004, Q014, Q021, Q033, Q044, Q054, Q063, Q072, Q080, Q084, Q086, Q092, Q093, Q096**이다. `docs/T11_execution_records.jsonl` 15행의 SHA-256은 `5d3d9a7df432cbfac741d479c554aae69a6dfbc8039ed166331d7f5a8d1b64b7`다. T14 대표 15개로 이 목록을 대체하지 않는다.

1. **기존 기록 무결성:** 기존 입력·정규화·모델/설정·top5 순위·본문·원문 세그먼트·인용·검토 메모를 대조한다. 기존 `execution.status=success`는 파이프라인 실행 성공이며 `SUPPORTED` 라벨이 아니다. Q044·Q086의 골드 미도달/한계 안내와 Q096의 반증을 유지하고 `manual_review=pending`을 검토 완료로 바꾸지 않는다. Q096의 골드 도달 플래그만 신뢰하지 않고 실제 반증 문서·세그먼트를 확인한다.

S 범위는 위 두 검색 노드와 최소 필터·원문 매핑 및 해당 검증에 한정한다. T17 상태 분류를 T11 성공 코드에서 추측해 만들거나 T16 루프·새 그래프 정점·검색 튜닝까지 포함해야 한다면 이 카드로 묶지 않고 해당 기존 태스크에서 먼저 계약을 구현한다.

## 6. 인계 순서와 완료 보고

1. T14-CONN 담당자가 §3의 필터·원문 매핑 계약을 T9/T13-2 담당자와 확정하고 검색 연결을 구현·검증한다. 연결 보고에는 검색 접합 통과, 답변 연결 미완료, 폴백 연결 미완료를 각각 명시한다.
2. T17 담당자는 T11의 기존 생성·인용 경로와 고정 `RetrievalBundle` 계약으로 T14-CONN과 **병행** 준비한다. 실제 검색 어댑터 준비 뒤 원질문·실제 근거로 `SUPPORTED/UNSUPPORTED/INSUFFICIENT_EVIDENCE` 및 인용 계약을 연결한다. Slice 1 15개 답변 대조와 CP2 표본을 재검증하고, T16이 준비되지 않은 기간의 근거 부족 종료 정책을 명시한다. 미연결 `RESEARCH` 오류를 정상 근거 부족 완료로 보고하지 않는다.
3. T16 담당자는 T17 상태 계약이 확정되면 대역으로 1회 예산·종료를 준비하고, 실제 T17 연결 후 명시적인 근거 부족과 요청 예산 0에서만 현재 항목의 재검색을 수행한다. 최초 재작성과 추가 재작성의 중복, 요청 전체 최대 1회, 출처·제약·원질문 유지, 재개 후 count 보존, 두 번째 근거 부족 종료를 검증한다.
4. T14-CONN·T17·T16을 실제 경로에서 함께 검증한 뒤 CP3를 판정한다. T15는 단독 T14 평가를 입력으로 병행할 수 있으며, 그래프 검색 설정·답변 경로와 합쳐 고정한 뒤 최종 스택 선정 게이트로 넘긴다. T15 전체 완료를 T14-CONN의 착수 조건으로 추가하지 않는다.

이 문서는 연결 소유·계약·검증 범위를 검토한 초안이다. 코드·테스트·기존 기록·태스크 카드는 수정하지 않았으며 커밋·푸시·PR을 수행하지 않는다.

### 7.3 공수와 실제 실행일 처리

| A-14 단독 + 연결 | 3h | T14-CONN은 이 기존 범위의 분해. 단독 사용 시간·남은 연결 예상 시간을 확인하고 부모/자식 합계를 중복 집계하지 않음 |
| A-15 검색 설정 | 3h | 기존 카드에 유지. 연결 A/B와 리랭킹·k 실험의 시간을 구분 |
| A-16 폴백 | 2h | 기존 T16에서 구현·연결·실제 1회 종료 검증을 추적 |

S는 작업의 분해 크기이며 실제 3시간 잔여 예산을 보장하지 않는다. 기존 실측 생성 호출의 합산 시간도 개발자 작업 시간과 같지 않다. 실제 사용·잔여 공수가 없으므로 이를 임의로 0h 또는 남은 3h로 기입하지 않는다.

WBS §8의 역할 예산에서 팀원 B의 여유는 0h다. T9 계약 검토·T17 연결·T15의 같은 담당자 작업을 무제한 병렬로 배정하지 말고 실제 담당별 가용 시간을 확인한다. 총가용 약 185h와 역할별 예산 합계 192h는 같은 숫자가 아니므로 역할표의 여유 23h를 전액 확정 버퍼로 가정하지 않는다. 이 초안에서 새 담당·예산을 확정하지 않는다.

WBS의 W3는 9/15~9/19, 중간발표 목표는 10/1이다. 현재 검토일 10/14는 원계획상 Phase B W7이다. 확인된 것은 이 코드 스냅샷에 Phase A 연결 공백이 남아 있다는 사실이며, 과거 발표 개최 여부나 Phase B 진행률은 검증하지 않았다. 기존 날짜를 새로운 착수일처럼 재사용하지 말고, 11/21 최종 마일스톤을 기준으로 연결·T17·T16의 실제 실행 순서·담당·잔여 공수를 보완해야 한다. 문서만으로 새 마감일을 확정하거나 Phase B 일정을 이동시키지 않는다.

### 7.4 우선순위와 검증 게이트

1. **기존 코어 접합:** T14-CONN과 T17을 계약부터 병행 준비하고 T16의 상태·예산 테스트를 이어 간다. 실제 검색·답변·1회 폴백을 합친 CP3 검증을 종료 조건으로 둔다. T14 검색만 붙인 상태에서 프로젝트 접합 완료로 보고하지 않는다.
2. **후속 검색·평가:** T15는 별도 수행하고 채택된 검색·문맥·답변 경로를 고정한 뒤 최종 스택 선정 게이트와 T23으로 넘긴다. 연결 보완 중 새 청킹·모델·검색 전략 실험을 필수 선행조건으로 끼워 넣지 않는다.
3. **실행 루프와 최종 통합:** T18~T22의 독립 개발과 Phase B 데이터·매핑은 직접 의존에 따라 진행한다. CP4/T25와 B-26/C-01에서 실제 서비스 전체 흐름을 별도 검증한다.

WBS §9에서 ④ 기본 Q&A와 렌더 루프는 최후까지 유지하는 코어다. 이 문서에서 T17 답변이나 T16의 계획된 폴백을 일정 조정의 묵시적 삭제 항목으로 두지 않는다. HyDE 보류는 검색 효과·가상 문서 위험에 따른 기술 채택 결정이며 재작성·근거 답변 전체를 보류하는 결정이 아니다. 추가 HyDE 실험은 코어 접합을 지연시키지 않는다. 일정 축소가 필요하면 정해진 순서(C-02 선택 UI, B-13 조건부 캡션, 후속 평가 축소)를 따르는 별도 범위 결정을 남긴다.

최종 답변 스택 선정 게이트는 WBS의 2026-10-01 추가 항목이며 담당·시간·실행일을 별도 배정하도록 명시돼 있다. T14-CONN처럼 기존 A-14 연결분을 분해하는 작업과 이 추가 실험을 같은 공수 처리로 묶지 않는다. 추가 실험 시간을 기존 W5 10h·Phase A 70h·전체 169h에 조용히 포함하지 않는다.
