# 채팅의 전체 수치 조정 확장

## 목표와 승인한 동작

사진 보정 도구의 수치 입력·슬라이더를 채팅으로 조정한다. 노출만 지원하던 제한을 제거하고, 꺼진 도구는 요청한 값을 적용할 때 함께 켠다. 주 창의 선택한 사진 또는 단독 편집기를 대상으로 하며 macOS·Unix socket·기본 OFF를 유지한다. 앱 환경설정, 파일 경로 선택과 임의 명령 실행은 사진 수치 조정에 포함하지 않는다.

사용 예: `채도를 20으로 설정해줘`, `색온도를 6500으로 설정해줘`, `샤프닝 반경을 0.8로 설정해줘`, `조정 가능한 항목 보여줘`. 단위·범위는 해당 GUI 입력과 같다. 일반 수치는 단위 접미사 없이 입력하며 단위 변환을 수행하지 않는다. 단위가 고정된 노출의 `EV`와 화이트밸런스 온도의 `K`만 접미사를 허용하고, 확인할 수 없는 단위는 적용 전에 거부한다. 같은 이름이 여러 도구에 있으면 후보를 안내하고 적용하지 않는다. 한 요청은 수치 한 항목을 변경한다. 상대값이나 값 없는 자동 보정은 임의로 추측하지 않는다.

## 구성과 작업 순서

| 구분 | 책임 | 선행 작업 |
|---|---|---|
| numeric-catalog | 모든 수치 위젯·범위·현재 값·도구·편집 문맥 조사 | 없음 |
| numeric-apply | 기존 GUI 경로를 통한 도구 켜기·수치 적용·히스토리 | numeric-catalog |
| numeric-ipc | 한정된 목록 조회와 문맥·대상·revision 검증 | numeric-apply |
| numeric-chat | 국문·영문 항목명 해석·목록·오류·완료 안내 | numeric-ipc |
| numeric-verification | 누락 항목 대조·출력 회귀·수명·메모리·스레드 검증 | 전체 |

기존 `tasks/plan.md`·`tasks/todo.md`는 변경하지 않는다. 이 문서가 이번 확장의 명세·체크리스트다. 전체 목록을 조사하며 항목을 줄여 완료를 선언하지 않는다.

## 설계 경계

### 수치 항목 목록

- `ToolPanelCoordinator`가 소유한 사진 도구에서 `Adjuster`, 일반 숫자 입력, 곡선 좌표 입력, 복합 임계값과 수치 슬라이더를 조사한다. 동적으로 생성한 LUT·로컬 보정의 수치도 같은 경로를 사용한다.
- 소스의 생성 지점 조사 결과는 53개 파일·250곳이다. `Adjuster` 216곳, 일반 숫자 입력 27곳, `ThresholdAdjuster` 4곳, `CoordinateAdjuster` 3곳이다. 반복 생성·동적 생성과 사진 도구 외 입력이 포함된 수치이므로 실제 지원 개수로 간주하지 않는다. 상세 조사 자료는 `build/liveparam-numeric-checks/source-inventory.json`에 둔다.
- 목록은 GUI 위젯의 실제 범위·간격·값과 현재 모드의 사용 가능 상태를 제공한다. `Adjuster` 안의 숫자 입력을 별도 항목으로 중복 등록하지 않는다. 숫자 값이 다른 항목과 연동되는 경우 기존 GUI와 동일한 연동을 유지한다.
- 식별자는 위젯 수명에 연결하고 해제 후 재사용하지 않는다. 기존 `Exposure.Compensation` 키는 보존한다. 표시 이름은 GUI의 도구명·항목명을 사용하고 국문·영문 번역을 연결한다.
- 로컬 영역·곡선 점·모드가 바뀐 뒤 같은 입력 위젯이 다른 대상을 가리키지 않도록 요청 전송 시 GUI의 문맥 식별자를 함께 복사한다. 문맥에는 도구가 기록하는 전체 GUI 파라미터와 수치 위젯의 현재 바인딩을 반영한다.

### 수치 적용

- 숫자·유한성·범위·사용 가능 상태·편집 대상·revision·문맥을 먼저 검증한다. 범위를 벗어난 입력을 조용히 잘라 적용하지 않는다.
- 검증 후 필요한 도구를 켜고 기존 위젯의 변경 경로를 사용한다. 도구 켜기와 연결된 값 변경으로 발생하는 이벤트는 요청 단위로 모아 엔진 전달·히스토리를 한 번 수행한다.
- Crop·Resize 등의 기존 연동 처리와 도구 이벤트를 보존한다. 화면 결과가 필요하지 않은 수치도 완료를 추측하지 않고 새 전체 갱신 세대의 Navigator·주 Crop 자료를 확인한다. `MINUPDATE`를 다른 이벤트와 합치지 않는다.
- 적용 전 오류는 값·도구 상태·히스토리에 흔적을 남기지 않는다. 적용 후 화면 준비 지연은 부분 완료로 안내하며 재전송·자동 되돌리기를 하지 않는다.
- 실행 중 `ProcessingJob`은 수정·재사용하지 않는다. 엔진 수식·처리 순서·프로필 형식은 변경하지 않는다. PPVERSION `1045` 유지의 전제는 수동 GUI와 외부 조정의 프로필·출력 일치 검증이다.

### IPC와 하위 호환

- 기존 v1 `get_state`, `set_param`, 노출 키, 오류 코드, 64 KiB·큐 제한과 완료 세대 규칙을 유지한다. 숫자 목록을 얻는 `list_params` 연산을 추가한다. 목록은 한 번에 최대 32개 항목과 다음 위치를 반환한다.
- `list_params`는 명시적 `sessionId`, `editorId`, `baseRevision`을 요구한다. 최초 조회는 현재 문맥을 발급할 수 있고, GUI 요청과 후속 페이지는 전송 시점의 `contextId`를 지정하여 같은 문맥만 조회한다.
- 일반 수치의 `set_param`은 목록에서 받은 키 하나, `contextId`, 명시적 `enableTool` 여부를 사용한다. 노출 전용 기존 요청의 도구 비활성 오류 동작은 보존한다. 새 채팅 경로는 `enableTool: true`를 명시한다.
- `APPLIED.effectiveParams`는 요청한 키의 실제 반영값을 반환한다. 요청 ID 캐시는 값뿐 아니라 키·기준 revision·문맥·도구 켜기 선택을 함께 대조한다. 같은 요청의 재조회는 GUI 상태가 변했어도 원래 반영 결과를 보존한다.
- 문맥 변경은 `REVISION_CONFLICT`, 없는 항목은 `UNSUPPORTED_PARAM`, 해당 모드에서 사용할 수 없는 항목은 적용 전 오류로 처리한다. 새 일반 수치 요청은 오래된 실행·사진·영역·곡선 점에 적용하지 않는다.

### 채팅과 GUI

- GUI가 현재 편집기·revision과 수치 문맥을 메인루프에서 소유 복사한다. 위젯·엔진 포인터를 외부 프로세스에 전달하지 않는다.
- Python은 등록된 전체 목록에서 항목을 찾는다. 일부 도구만 하드코딩한 목록으로 지원 범위를 제한하지 않는다. 대표 표현의 동의어는 전체 목록 위에 추가한다.
- 명확한 항목명과 절대값만 적용한다. 질문·부정문·인용·여러 수치가 섞인 모호한 요청은 적용하지 않는다. 목록 안내는 페이지와 도구 필터를 제공하여 결과 크기를 제한한다.
- GUI 허용 설정·도움말을 전체 사진 수치 조정에 맞춰 갱신한다. 일반 Q&A는 계속 동작한다. 숫자 조정은 검색 저장소나 외부 답변 호출 없이 처리한다.

## 검증 명령

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 6 --target art art-cli test_liveparam_gui test_liveparam
build/rtgui/test_liveparam_gui
build/rtgui/test_liveparam
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src /Users/user/Workspace/Programming/Projects/AAART/venv/bin/python3 -m pytest tests/test_live_param.py tests/test_live_param_cli.py tests/test_live_param_chat.py tests/test_gui_bridge.py -q
cmake --build build/asan --parallel 6 --target art art-cli test_liveparam_gui
cmake --build build/tsan --parallel 6 --target art art-cli test_liveparam_gui
```

빌드는 모두 `build/` 아래에서 수행한다. `-ffast-math`, in-source 빌드, 기존 검사 완화는 금지한다. 전체 수치 목록과 세부 시나리오의 실제 결과는 구현하면서 이 문서에 기록한다.

N1의 GUI·CLI 빌드는 `n1-fixed-build.log`, 실제 목록은 `n1-catalog.json`에 기록했다. 현재 목록은 모드별 지원 상태를 포함하며 이 숫자를 모든 모드의 최종 항목 수로 표시하지 않는다. 현재 GUI의 실제 목록 전체를 채팅에서 조회·적용하며, 최종 회귀 증거는 N5에서 확인한다.

N2의 공통 트랜잭션과 위젯 적용 경로를 구현했다. `T20`에서 꺼진 채도의 활성화·값 적용이 히스토리와 revision을 각 1회만 증가시키고 나머지 파라미터를 보존함을 확인했다. 화이트밸런스 온도 변경은 기존 Custom 전환, 리사이즈는 기존 숫자 입력 경로를 따른다. 켜기 버튼이 없는 상시 도구도 불필요한 활성화 없이 적용했다. `T19/T20` 종료 코드 `0`(`n2-final.log`). 복합 임계값·색상 휠·곡선 좌표 등의 추가 실제 적용 시나리오는 N5에서 별도로 검증한다.

N3의 `list_params` 결과는 `revision`, `contextId`, `items`, `total`, `nextOffset`을 사용한다. 각 항목은 `key`, `tool`, `toolLabel`, `label`, `min`, `max`, `step`, `value`, `enabled`, `available`, `pending`을 제공한다. 이어지는 페이지는 같은 문맥을 요구한다. Python의 전체 목록 조합은 총 4 MiB와 단조 시계의 기한으로 제한하며, 초과·중복·변경을 성공으로 잘라 반환하지 않고 오류로 처리한다. 일반 수치는 기존 `set_param`에 목록의 키 하나와 `contextId`, `enableTool`을 명시한다. 응답의 `enabledTools`는 이 요청에서 실제 켠 도구다. 기존 노출 전용 요청의 응답 형식은 유지했다.


N4는 `numeric_context_id`를 GUI 전송 시 복사하고, 전체 페이지에서 국문·영문 항목명을 찾도록 연결했다. 기본 도구의 대표 수치(예: 채도)는 도구명만으로 지정하고, 다른 도구의 같은 이름은 도구명과 함께 지정한다. 그 밖의 중복 이름은 적용하지 않고 후보를 안내한다. 목록은 20개씩 표시하고 도구 필터·페이지·항목 번호를 제공한다. 번호는 현재 편집기 목록 기준이므로 모드를 바꾼 뒤에는 목록을 다시 확인한다. 일반 이름의 근거는 실시간 GUI 목록과 `rtdata/languages/default`·`Korean` 번역이며 일부 키의 허용 목록으로 제한하지 않는다. 허용 체크박스·도움말은 전체 사진 수치 조정 및 비활성 도구의 자동 켜기를 명시한다. 기존 `live_exposure` 저장 키는 설정 호환을 위해 유지한다.

`T22`에서 실제 채팅→Python→Unix socket→GUI로 채도·온도·리사이즈·현재 샤프닝 모드의 반경을 적용했다. GUI 상태만 바뀌어 revision이 그대로인 경우에도 전송 시 문맥이 다르면 거부했다. `T16`의 기존 노출·취소·닫기 검증도 통과했다(`n4-native-final.log`, 종료 코드 `0`). Python 명령·목록·모호성·오류와 기존 노출 채팅 45건이 통과했다(`n4-chat-green.log`, 종료 코드 `0`). GUI에서 찾은 일반 채도와 색상 휠의 동명 충돌, 빈 도구 제목을 수정했다.

`T23`은 일반 Spin·Range, 임계값의 네 핸들, SHC 경계, 색상 휠 두 종류, 곡선 좌표의 정규화·선택 변경, 동적 LUT 생성·재생성 수명을 실제 위젯으로 검증한다. 정수 입력은 GTK의 표시 정밀도 확정 경로를 거쳐 실제 저장값을 응답한다. `T24`는 USM/RL/PSF·Resize 5모드·화이트밸런스 5모드·색 보정 5모드·파라메트릭/제어점 곡선·동일 값의 로컬 영역 전환을 포함한 23개 상태를 기록했다(`n5-modes-green.log`, 종료 코드 `0`). 이 조합 수와 표시 이름 조합 수를 전체 모드의 최종 지원 개수로 간주하지 않는다.

`T25`에서 일반 Adjuster·화이트밸런스·Resize Spin·복합 임계값·색상 휠을 적용할 때마다 revision·히스토리가 각 1회 증가했다. 독립적인 수동 위젯 콜백 경로와 모든 `ProcParams`가 일치했고, TIFF 픽셀의 최대 절대 차이가 `0`이었다(`n5-output-green.log`, 종료 코드 `0`). `rtengine/`·프로필 형식·수치 의미를 변경하지 않았으므로 PPVERSION `1045`를 유지한다.

수치 위젯 생성 지점의 대조는 다음 경계를 사용한다. 일반 `Adjuster`와 숫자 Spin·Range는 도구 트리에서 자동 조사하며, 그 내부 입력을 다시 등록하지 않는다. `ThresholdSelector`·`ColorWheel`의 임시 숫자 팝업은 복합 위젯의 동일 성분으로 연결한다. `CoordinateAdjuster`·파라메트릭 곡선의 `SHCSelector`는 현재 선택한 점과 경계로 연결하고, 동적 LUT와 마스크의 하위 입력도 소유 도구 안에서 같은 방식으로 조사한다. `preferences`·`dynamicprofilepanel`·`saveformatpanel`·브라우저 필터·파일 이름 변경·글꼴·히스토그램 표시 밝기는 현재 사진의 보정 도구가 아니므로 포함하지 않는다. 새 일반 수치 위젯이 도구에 붙으면 별도의 키 허용 목록 없이 목록에 포함된다.

모드·영역·곡선 점은 GUI에서 선택한 현재 대상을 따른다. 사용할 수 없는 입력은 목록에 사용 불가로 표시하며 모드나 점을 임의로 바꾸지 않는다. 여러 숫자를 한 번에 추측해서 바꾸거나 상대값·자동 보정·프로필 전체 적용을 추가하지 않았다.

현재 작업용 앱은 `build/liveparam-numeric-checks/ARTChatControls.app`이며 이전 실행 앱과 다른 번들·설정·캐시를 사용한다. 사진을 편집기에 연 뒤 채팅의 **연결 설정 → 채팅으로 사진 수치 조정 허용**을 켜고 요청한다. 명령행 옵션이나 환경변수를 직접 입력할 필요가 없다. 예:

- `채도를 20으로 설정해줘`
- `색온도를 6500으로 설정해줘`
- `샤프닝 반경을 0.8로 설정해줘`
- `조정 가능한 항목 보여줘`
- `채도 조정 가능한 항목 보여줘`
- `조정 가능한 항목 2페이지 보여줘`

한 요청은 절대값 한 항목을 적용한다. 같은 이름이 겹치면 도구명이나 현재 목록의 항목 번호를 지정한다. 비활성 도구는 적용과 함께 켜지고 그 전체가 히스토리 한 행에 기록된다. 기본값은 OFF이며 네트워크 노출·별도 상주 프로세스·다른 OS 지원은 추가하지 않았다.

## 병합 전 검토

최종 검토에서 단위 접미사를 읽고도 GUI 단위와 대조하지 않는 문제를 확인했다. 예를 들어 Resize가 cm 모드인 상태에서 `px`를 붙인 요청을 그대로 숫자로 적용할 수 있었다. 확인할 수 없는 단위는 적용 전에 거부하고, 고정된 노출 `EV`·온도 `K`만 허용하도록 수정했다. 단위 변환이나 지원 항목의 허용 목록을 추가하지 않았다.

회귀 검사에서 잘못된 단위를 붙인 5건의 실제 적용을 먼저 재현했다(`build/liveparam-review-checks/units-red.log`, 실패 5건). 수정 후 클라이언트·CLI·수치 목록·노출/일반 수치 채팅·GUI 연결 131건과 실제 GUI `T16/T22`가 통과했다(`client-chat-green.log`, `gui-chat-final.log`, 종료 코드 `0`). C++·엔진·프로필 형식 변경은 없으므로 앞 절의 Release·ASan·TSan 전체 검증 결과를 유지한다. 기본 OFF·대상/문맥 고정·중복 요청 처리·도구 활성화의 단일 히스토리·입력 경계·기존 노출 API를 검토했고 추가 병합 차단 사항은 발견하지 못했다.

이전 클라이언트 플랜의 현재 사용 안내는 새 앱 경로·사진 수치 조정 허용 이름·호환 저장 키·단위 규칙으로 정리했다. 초기 노출 전용 구현 이력과 현재 전체 수치 확장의 기준을 구분한다.
