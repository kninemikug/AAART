## 3. 수정 A — 실제 외부 원문 경로를 항상 보호

`validate_record_path()`가 보호 목록을 구성할 때 다음 세 루트를 사용한다.

| 보호 대상 | 규칙 |
| --- | --- |
| 각 원문 루트의 `data/rawpedia`, `data/issues`, `data/vector-store` | 디렉터리 자체와 모든 하위 경로 거부; 아직 없는 출력 파일도 거부 |

검사 대상과 보호 경로 모두 절대경로로 정규화하고 심볼릭 링크를 해석한다. 경로 포함 관계는 경로 API로 판단한다. 문자열 접두어 비교나 파일 확장자만으로 보호 여부를 판정하지 않는다.

### 3.2 호출 순서와 오류

CLI는 `run_pipeline()`을 호출하기 전에 같은 검사를 수행한다. `run_pipeline(record_path=...)`를 직접 호출하는 경우에도 T09 준비·검색·생성 전에 검사한다. 두 진입점은 동일한 보호 목록을 사용한다.

거부 시 CLI는 `[validation]` 오류와 종료 코드 2를 반환한다. `run_pipeline()` 직접 호출은 검증 예외를 반환 경계로 전달한다. 금지된 파일이나 그 부모 디렉터리를 생성·열기·추가 쓰기 하지 않는다. 경로 검사 실패는 LLM 실행 실패 기록과 구별한다.

## 4. 수정 B — Codex 이벤트를 엄격하게 검증하고 기록

### 4.1 실행 조건 고정

기존 임시 작업 폴더, `--ephemeral`, `--json`, `-o`를 유지한다. 추가로 사용자 설정의 자동 적용을 끄고 read-only sandbox를 명시한다. 설치된 CLI가 지원하는 설정으로 shell/exec와 웹 검색을 비활성화하고, 자동 연결된 MCP 도구가 없도록 실행 조건을 고정한다. 현재 공식 설정의 `features.shell_tool`, `features.unified_exec`, `web_search`와 MCP 활성화 설정을 참고하되 설치 버전에서 지원 여부를 먼저 확인한다. 옵션 오류가 나면 옵션을 몰래 제거하거나 다른 제공처로 전환하지 않는다. [Codex 설정 참조](https://learn.chatgpt.com/docs/config-file/config-reference)

현재 설치 CLI의 도움말에서 `--ignore-user-config`, `--ignore-rules`, `--sandbox`, `--json`을 확인했다. 인증 정보는 기존 방식으로 재사용하고 사용자 전역 설정 파일 자체를 수정하지 않는다. `--ignore-rules`를 사용할 경우 명시적 sandbox·도구 비활성화 설정과 함께 적용하고, 사용한 정책을 기록한다. [비대화형 실행 문서](https://learn.chatgpt.com/docs/non-interactive-mode)

임시 작업 폴더와 read-only 정책만으로 절대경로 읽기가 완전히 차단됐다고 주장하지 않는다. 성공 판정에는 아래의 이벤트 검증도 반드시 적용한다. 이 절의 설정은 추가 도구 사용을 줄이는 실행 조건이며, 성공 로그를 대신하지 않는다.

### 4.2 T11 성공 이벤트 계약

`--json` stdout의 모든 비어 있지 않은 줄을 JSON 객체로 파싱한다. JSON 형태처럼 보이는 줄만 골라 읽거나 파싱 예외를 무시하지 않는다. 다음은 T11의 단일 생성 실행을 검증하기 위해 추가할 계약이다.

| 항목 | 성공 조건 및 거부 조건 |
| --- | --- |
| 로그 존재·구조 | 비어 있지 않고 모든 비어 있지 않은 줄이 유효한 JSON 객체이며 이벤트 `type`이 있음; 빈 로그·잘린 JSON·일반 텍스트·잘못된 구조는 거부 |
| 생명주기 | `thread.started`, `turn.started`, `turn.completed`가 순서대로 확인되고 시작·완료 turn이 각각 1회; 미완료·중복 turn은 거부 |
| 오류 | `turn.failed`, `error` 또는 비정상 프로세스 종료는 거부 |
| 항목 이벤트 | 설치 CLI에서 확인한 `item.started`, `item.updated`, `item.completed`를 처리; 항목 유형이 없거나 알 수 없는 유형이면 거부 |
| 허용 항목 | `agent_message`, `reasoning`만 허용. 다른 유형을 허용해야 한다면 실제 CLI 계약을 확인하고 근거와 테스트를 먼저 남김 |
| 추가 도구 | 명령 실행, 파일 변경, MCP, 웹 검색 및 기타 도구 항목은 시작·갱신·완료 중 어느 위치에 있어도 거부 |
| 최종 답변 | 완료된 최종 `agent_message`가 있고, 그 메시지와 `-o` 파일을 같은 JSON 파서로 읽었을 때 `answer`·`citation_ids`가 일치 |
| 알 수 없는 이벤트 | 조용히 건너뛰지 않고 검증 오류로 기록; 이후 자동 재시도 없음 |
| 사용량 | `turn.completed`가 제공한 usage를 보존. 없는 값은 null; 텍스트 정규식 결과로 이벤트 검증 실패를 보충하지 않음 |

이벤트 검증 실패 후 인용 검증이나 성공 출력으로 진행하지 않는다. 정상 이벤트를 확인한 뒤 기존 답변 JSON·인용 검증을 그대로 적용한다. 추가 도구 사용 판정은 사후 탐지이므로 실제 사용이 있었다면 실패 기록에 남긴다.

### 4.3 실행 기록의 보존 계약

별도 이벤트 파일 대신 각 실행의 `generation.trace`에 CLI stdout과 검증 결과를 함께 저장한다. 기존 실행 기록 필드는 보존하고 trace에 자체 버전을 둔다. 기존 로그가 없는 기록에 빈 trace를 붙여 새 검증을 통과한 것처럼 처리하지 않는다.

| `generation.trace` 필드 | 명세 |
| --- | --- |
| `trace_schema` | `t11-codex-trace-v1` |
| `cli_version`, `process_returncode` | 실행 CLI 버전과 실제 종료 코드; 시간 초과 등 미확인 값은 null |
| `execution_policy` | 사용한 모델 ID, 작업 폴더 방식, sandbox, 사용자 설정 적용 여부, 도구 관련 옵션. 자격증명 제외 |
| `stdout_jsonl` | 수신한 전체 이벤트 스트림; 순서·실패 줄·미지 이벤트도 보존 |
| `stderr` | 실패 원인 대조에 필요한 CLI 진단; 자격증명 제외 |
| `validation` | `status`(verified/rejected/unavailable), 이벤트 개수, thread ID, 시작·완료 turn 개수, 관찰 항목 유형, 추가 도구 개수, 오류 줄·사유 |

파싱한 이벤트 배열은 검증 중에 사용하고 원본 stdout에서 다시 만들 수 있게 한다. 답변 텍스트가 포함된 이벤트를 기록에서 제거하지 않는다. 로그에 비밀값이 있다면 그 값만 제거하고 제거 여부를 표시하며, 검증에 필요한 이벤트 종류·순서·구조는 유지한다.

생성 함수가 예외를 던지는 경우에도 수집한 trace를 `run_pipeline()`의 오류 기록으로 전달한다. 최소한의 내부 예외 데이터 전달 방식을 사용하고 전역 변수에 실행 상태를 저장하지 않는다. 비정상 종료·시간 초과는 확보한 부분 stdout/stderr를 남긴다. 수신된 로그가 없으면 trace 상태를 unavailable 또는 rejected로 명시한다.

`generation.call_count=1`은 해당 생성 호출을 시도했다는 뜻이다. trace 실패 실행은 `execution.status=error`, `failed_step=generation`, 0이 아닌 종료 코드로 기록하고 성공한 대표 질문으로 세지 않는다. CLI가 제공하지 않는 temperature·finish reason은 계속 null로 둔다.

### 4.4 필수 회귀 테스트

Codex 프로세스는 모의 실행으로 대체하고 답변 파일과 이벤트는 테스트용 임시 디렉터리에 생성한다. 단위 테스트에서 실제 LLM을 호출하지 않는다.

| 입력 | 기대 결과 |
| --- | --- |
| 정상 이벤트 + 일치하는 최종 답변 | 성공; trace가 최종 JSONL에 남고 다시 파싱·검증 가능 |
| 빈 stdout + 정상 답변 파일 | 생성 오류; 성공으로 처리하지 않음 |
| 잘린 JSON·비JSON 줄·필수 필드 누락 + 정상 답변 파일 | 생성 오류; 문제 줄과 trace 보존 |
| 완료 이벤트 누락·turn 중복·오류 이벤트 | 생성 오류 |
| command/file-change/MCP/web-search 항목 | 생성 오류; 추가 도구 판정과 원본 이벤트 보존 |
| 도구 항목이 `item.updated`에만 나타남 | 생성 오류 |
| 이벤트의 최종 답변과 `-o` 파일 불일치 | 생성 오류 |
| 프로세스 비정상 종료·시간 초과 | 생성 오류; 확보한 부분 로그 보존 |
| 실패 이벤트를 넣고 CLI의 안전한 `--record` 사용 | 실제 저장된 JSONL에 오류 상태와 trace가 있으며 성공 stdout 없음 |
| 제공처 설정 부족 | 기존처럼 해당 제공처 오류; 자동 전환·재시도 없음 |

**체크포인트 B:** 정상·실패 trace가 실제 기록 경로까지 전달되고, 저장한 trace만으로 같은 판정을 재현할 수 있어야 한다. 생성 함수 내부 검사와 토큰 수 저장만으로 통과 처리하지 않는다.

## 6. 15개 재실행과 최종 합격 기준

Q001을 첫 실행으로 사용해 trace와 최종 기록이 정상인지 확인하고, 통과하면 나머지 14개를 같은 설정으로 순차 실행한다. 첫 실행이 실패하면 원인을 기록하고 배치 진행을 멈춘다. 수정 후의 의도적인 새 실행은 별도 시도로 식별하며 실패를 숨기는 자동 재시도를 하지 않는다.

새 실행은 최종 파일과 구별되는 안전한 시도 기록 경로에 먼저 남긴다. 이전에 커밋된 기록은 Git 이력에서 추적 가능하게 유지한다. 실패 기록은 보존하고, 검증된 새 실행이 15개 확보된 뒤 `docs/T11_execution_records.jsonl`에 ID별 최종 실행 1개씩 반영한다. 과거 기록의 usage나 검토 메모를 복사하여 새 실행 증거로 사용하지 않는다.

- [ ] 환경변수가 없는 외부 원문 경로와 추가 루트 경로 모두 사전 거부된다. 금지 경로 테스트에서 검색·생성·파일 쓰기 호출이 0이다.
- [ ] 빈·깨진·미완료·도구 포함 이벤트는 실패하며, 실패 trace도 기록에 남는다.
- [ ] 최종 기록은 지정 순서의 15개이며 질문 ID·run ID가 중복되지 않는다. 원문 질문과 절대경로 질문셋의 SHA가 일치한다.
- [ ] 모든 성공 기록의 trace가 독립 재검증에 통과한다. 단일 turn, 추가 도구 0개, 완료 agent message와 생성 파일의 답변 일치가 확인된다.
- [ ] 실제 T09 검색 1회·생성 호출 1회, 검색 문맥·프롬프트·인용·stdout의 일치와 원문 세그먼트 해시·범위를 확인한다. 테스트의 모의 객체 결과를 실제 검색 증거로 세지 않는다.
- [ ] Q001·Q086·Q096의 새 답변을 다시 수동 검토하고 메모를 기록한다. Q086에서 여전히 근거가 검색되지 않으면 그 한계를 지킨 답변인지 확인한다.
- [ ] Q001·Q004·Q014·Q054·Q063 등 서로 다른 양성 질문 5개의 주요 사실·인용을 확인하고 각 ID·run ID를 검토 메모에 남긴다. 확보되지 않으면 CP2 완료로 보고하지 않는다.
- [ ] Q044·Q086 등의 검색 누락을 감추지 않는다. 검색 누락 자체를 이유로 T09 설정을 바꾸지 않으며, Q096의 없는 JXL 슬라이더 절차를 생성하지 않았는지 확인한다.
- [ ] 수정 파일, 테스트 명령과 실제/모의 검증 범위, 최종 15개 기록 경로를 보고한다. 원본 질문셋과 T09 파일이 변경되지 않았는지 diff·지문을 확인한다.
