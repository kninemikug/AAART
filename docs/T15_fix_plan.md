## 3. F01 — 판정과 보고서 분리, 실패를 실패로 반환

**의존:** 없음. **규모:** S. **예상 파일:** `scripts/eval_t15_rerank.py`, `tests/test_t15_rerank_eval.py`.

원시 기록에서 지표·계약 검증 결과를 계산하는 함수와 게이트 판정 함수를 먼저 분리한다. 보고서는 판정 결과와 사유만 렌더링하고 자체적으로 PASS 문자열을 결정하지 않는다. `run`과 `check`가 같은 판정 규칙을 소비하도록 한다. 실행/파일 저장 성공과 품질 게이트 통과는 별개다.

| 판정 | 적용 기준 | CLI 종료 코드 |
| --- | --- | ---: |
| `FAIL` | 실제 수치/개별 순위 퇴행, 원문·상태·인용·제품 범위 위반, 중복/불일치 등 확인된 위반 | 1 |

## 4. F02 — 질문·반증 ID와 on/off 지표를 단일 경로로 계산

**의존:** F01. **규모:** S/M. **예상 파일:** `scripts/eval_t15_rerank.py`, `tests/test_t15_rerank_eval.py`.

원본 질문 JSON에서 양성의 `gold_support_doc_ids`를 읽고, 부정의 반증 집합은 **`evidence[].doc_id`에서 중복 제거하여 도출**한다. T14 A/B의 `counter_evidence_doc_ids`와 전수 대조하고 prepare·grid·regression·check가 같은 함수를 사용한다. 필수 입력 누락을 빈 집합으로 보정하지 않는다.

검색 문서 집합은 실제 `source_segments[].doc_id`를 사용한다. 세그먼트가 없거나 손상되면 그룹/상위 `hit.doc_id`로 대체해 정상 근거로 세지 않는다. 선택된 모든 세그먼트·인용 매핑을 검증하고 같은 원문 ID의 중복만 제거한다. 최종 순위는 선택 목록 순서/최종 rank로 계산하며 원래 dense rank와 구별한다.

양성 precision·recall, 원시 교집합/선택/골드 수, macro·micro, Hit@5/MRR@5와 최종 @k를 재계산한다. 부정의 지원 precision·recall은 N/A로 저장하고 별도의 반증 precision·recall·도달을 계산한다. 누락 질문은 0점 기본값으로 숨기지 않고 완전성 위반으로 처리한다.

G2는 B 대 B0, A 대 A0를 각각 비교한다. 전체95·RawPedia80·GitHub15·Slice 1 양성14의 precision/recall 및 고정 Hit@5/MRR@5를 모두 확인한다. G3는 B의 양성95개 각각과 A0에서 도달했던 각 질문의 최초 골드 순위를 비교하고, 부정5개도 **질문별로** 기존 반증 도달을 보존하는지 확인한다. 전체 평균·반증 총합만으로 개별 손실을 상쇄하지 않는다. 판정에는 원시 분수/정수 합을 쓰고 반올림은 표시에서만 한다.

**완료·검증 기준:**

## 5. F03 — 실제 pair 인코딩에 맞춘 채점 윈도우

**의존:** F01. **규모:** S/M. **예상 파일:** `src/artagent/retrieval/rerank.py`, `tests/test_rerank.py`.

특수 토큰3개 상수를 제거하고 해당 토크나이저의 pair 특수 토큰 수와 모델의 실제 한도로 예산을 계산한다. 사용자 `max_length`·토크나이저·모델 한도와 모델에 전달하는 최대 길이를 일치시킨다. 문자열 decode→재인코딩과 제목/구분자 결합으로 토큰 수가 증가할 수 있으므로 **최종 pair의 truncation 전 실제 길이**를 검사한다.

길이를 초과하면 원문 범위를 보존하며 본문 윈도우를 줄여 다시 구성하거나 명시적으로 실패시킨다. 기본 truncation에 의존해 조용히 자르지 않는다. 겹침64·제목 최대32·`max_window_v1`은 별도 조건 변경이 없는 한 유지하며, 모든 실제 세그먼트의 채점 범위·원문 문자/바이트 위치·pair 길이·원시 점수를 기록해 누락0을 확인한다. 선택 청크의 Evidence는 계속 전체 원문 세그먼트를 유지한다.

질의/제목 때문에 본문 예산이 없으면 오류로 끝낸다. 원시 logit→sigmoid 한 번의 변환을 유지하고 극단값·비유한 값·점수 개수 불일치를 명시적으로 다룬다. 모델별 입력 처리를 바꾼 뒤 기존 점수 캐시를 재사용하지 않는다.

**완료·검증 기준:**

- [ ] R1(pair 특수 토큰4)·R2(실제 토크나이저 값)에서 모든 전달 pair가 유효 한도 이하다. 기존513·514토큰 반례가 사라진다.
- [ ] 한도 직전/정확히 한도/초과, 제목 결합·재인코딩 팽창, 긴 질의, 긴 청크의 마지막 단어·후반 근거를 검증한다. 단순히 윈도우 수≥2만 단언하지 않는다.
- [ ] 단위 테스트는 실제 전달 인코딩·원문 범위를 검사하고, 고정된 실제 로컬 모델 smoke 확인으로 보완한다. 원문·위치·최종 Evidence 본문이 바뀌지 않는다.

## 8. F06 — 실제 검색·그래프 경유 전체 회귀

**의존:** F01~F05 및 검색 집중 테스트 통과. **규모:** S/M. **예상 범위:** 평가기와 검색 연결 테스트의 최소 보완, 새 평가 기록. 서비스 코드 변경은 실제 계약 오류가 확인된 경우에만 한다.

평가 전용 `SnapshotStoreAdapter`나 별도의 검색 구현이 서비스의 ready/규격·원문 검사·필터를 대신하지 않도록 실제 `RetrievalStore` 경로를 사용한다. 같은 고정 스냅샷·T9 설정의 격리 저장소를 현재 작업 위치의 평가 폴더 또는 임시 디렉터리에 준비한다. 다른 워크트리·터미널을 조작하지 않는다. 출처/지정 글 필터, 명시적 빈 글 목록, 제외 상태, 기본10→5 호환을 검증한다.

G0는 A0/B0의 top5 ID·순서·거리 정렬·원문 위치·지표를 모두 대조한다. 전체 precision/recall 두 숫자만 같다고 기준선100% 재현으로 판정하지 않는다. T14의 준비된 질의/생성 이벤트는 동일 입력·보존 정책의 검증된 재생으로 연결하고 일반 서비스 생성기로 전용하지 않는다.

G1은 `create_router_graph(node_overrides=...)`로 **실제 그래프**를 실행한다. 20개 고정 요청을 on/off 각20개씩 실행하여 primary path·plan·clarify·first branch·trace·필터·상태 보존을 대조한다. 기대 first_branch를 읽어 검색 노드를 직접 선택한 뒤 bundle 존재만 검사하는 방식은 제거한다. 답변 대역을 쓰는 검색 계약 시험은 대역임을 남기고 G5/CP3 증거에서 제외한다.

고정 후보는 전체100개 on/off를 **3회 실제 검색·채점**한다. 각 반복에서 전체 후보/선택 ID·순위·점수와 질문별 지표를 보존하고 비교한다. Slice 1 평균이 세 번 같다는 이유만으로 전체 순위 재현을 통과시키지 않는다. Slice 1의15개는 별도 대조표로 제시하고 양성14·부정1을 구분한다. 채점 p50/p95·cold load·메모리 및 실제 문맥 크기를 보고한다. 이전 기록의 on 채점 중앙값 약5.23초·p95 약7.30초는 참고이며 수정 후 새로 측정한다.

**완료·검증 기준:**

## 10. 실행 순서·검증 명령·일정

순서는 **F01 → F02/F03 → F04·F05 → 기존 v1 감사 → F06 → F07 → 최종 독립 검증**이다. F02/F03은 논리 의존이 없지만 공유 파일 변경은 순차 적용한다. 각 단계는 반례를 먼저 고정하고 최소 수정 후 관련 검증을 통과한다. 체크포인트를 건너뛰어 긴 실험을 먼저 실행하지 않는다.

| 체크포인트 | 입력 → 출력 | 다음 단계 조건 |
| --- | --- | --- |
| A: F01~F03 | 실패 반례·기존 입력 → 판정/ID/윈도우 수정·집중 테스트 | 실제 판정 함수를 검증하고 반증5/5·pair 한도를 재현 |
| B: F04~F05 | 고정 코퍼스·모델·기록 계약 → 유효 후보 비교/독립 검증기·v1 감사 | 원본 불변, 잘못된 기록의 PASS 차단, 새 실행 지문 고정 |
| C: F06 | 새 격자·채택 가능 후보 → 전체 회귀/경로·반복 기록 | G0~G4·양경로 비저하·개별 퇴행0. 미달이면 B0 유지 |
| D: F07 | C 합격 후보·실제 T17 → 답변/인용·검토·G5 | 최종 `check`가 검색/생성 없이 재계산하여 PASS |

아래 pytest 명령은 현재 존재하는 파일을 쓰며, 추가될 반례도 같은 파일에 포함하는 계획이다. v1의51개 통과 수를 후속 수정의 고정 예상 개수로 사용하지 않는다.

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src:. HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 /Users/user/Workspace/Programming/Projects/AAART/venv/bin/python3 -m pytest -p no:cacheprovider tests/test_rerank.py tests/test_t15_rerank_eval.py tests/test_graph_search_connection.py tests/test_retrieval.py -q
```

집중 검증을 통과한 뒤 검색·답변·평가 계약을 함께 바꾼 범위에 대해 전체 회귀를 한 번 수행한다. 이후 재실행은 새 변경·실패·남은 우려가 있을 때만 한다.

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src:. HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 /Users/user/Workspace/Programming/Projects/AAART/venv/bin/python3 -m pytest -p no:cacheprovider tests -q --tb=short
```

새 prepare/grid/regression/t17 실행 명령은 [기존 플랜 §5.3](T15_execution_plan.md#53-평가-실행기와-재실행-명령)의 CLI를 유지하고 출력만 v2의 새 위치로 바꾼다. 보완 후 `check`에는 원본 protocol·선정 설정·검토·감사 출력 연결이 필요하다. 아래 추가 플래그는 **후속 설계이며 현재 구현된 것으로 취급하지 않는다.**

독립 검증은 입력 파일들의 SHA·크기·mtime을 전후 대조하고 감사 결과만 별도 위치에 쓴다. 보고서 재생성이 필요하면 명시적인 별도 쓰기 단계로 수행한다. 격자/실제 생성은 이 플랜 작성 중 실행하지 않는다.

일정은 착수 T0의 체크포인트 A → T1의 B/격자 → T2의 C → 실제 생성 예산·검토가 확보된 뒤 D 순으로 잡는다. 실행 담당은 김구이며 T17 연결 검증과 T13-2 라우팅 잔여는 해당 카드 담당과 연계한다. 기존 A-15의3h를 수정하지 않고 이번 보완의 추가 실작업·계산 대기·생성/수동 검토 시간을 별도 기록한다. 구체적인 호출/시간 예산은 실제 실행 전 protocol에 고정하며 초과나 한도 오류를 누락하지 않는다.
